# D1 · Parallel execution under the 60-second round deadline

**Recommendation.** Build one monotonic submission writer and give it a complete deterministic candidate by +5 s, with an acknowledgment target of +10 s. Start a compact, text-only invoice call and a price-focused stronger call in parallel. Freeze the best validated snapshot at +54 s. Allow one narrowly scoped backup for a stalled or failed strong call, plus no extra calls for lines where the available evidence already supports the same decision.

Research date 2026-11-21. This is a design and source review. Timing thresholds below are starting budgets for replay, and model quality and latency have yet to be measured on this workload. Only released case 0 and local documentation are available for this slice. Actual fair thresholds `t` and counterparty behavior are unknown. The API applies defaults of `(a, b) = (0, 0)` to omitted lines, so a missed submission still participates. [Shared context](CONTEXT.md) · [API handbook](../../materials/API_HANDBOOK.md#put-apigamesgame_idsubmissions) · [Evaluation criteria](../../materials/EVALUATION_CRITERIA.md)

## Current path and its failure modes

- The runner times from function entry, then performs key retrieval, decryption and case loading in sequence. Both model calls start after those steps. A late start steals time from the real deadline. Synchronous pricing, log writes and PUTs also run between checks of the local deadline. The game client gives each HTTP call a 10-second timeout, and the runner can immediately retry a failed full-tier PUT. A local wait timeout therefore does not bound wall-clock completion. [Runner](../../claimbot/runner.py#L55) · [Game API client](../../claimbot/api.py#L17)
- The runner iterates an unordered set of completed futures. When both finish together, the low-effort write can follow the medium-effort write. It also marks the full tier done after a failed retry. Cancelling a future or shutting down its executor with `cancel_futures=True` cannot stop a thread that is already running. [Runner](../../claimbot/runner.py#L87) · [Python futures](https://docs.python.org/3/library/concurrent.futures.html#concurrent.futures.Executor.shutdown)
- Each estimate creates its own OpenAI client, encodes the same photos at high detail, returns duplicated invoice fields and prose, and waits for one complete parsed response. Both calls use the same configured model and project. They provide effort diversity with a shared failure domain. [Estimator](../../claimbot/estimator.py#L46) · [Schema](../../claimbot/schema.py)

## Evidence and implications

### Tail latency and hard deadlines

- **Dean and Barroso, *The Tail at Scale*, February 2013, pp. 76–77 [opened].** ACM publication, no open reuse licence stated on the author copy. In the “Hedged requests” section, delaying a backup until the primary class's p95 targets about 5% extra requests. In a Bigtable benchmark, a 10 ms hedge reduced p99.9 for a 1,000-key read from 1,800 ms to 74 ms, with 2% extra requests. Tied requests arrange cross-server cancellation when one starts. Public model APIs generally expose client-side abort at best, so the benchmark's latency and work savings are workload-specific. Transfer first-success semantics only to candidates that pass validation and have the same assigned role. Replay the same input with correlated latency and estimate incremental billable tokens separately. [Author's paper](https://www.barroso.org/publications/TheTailAtScale.pdf) · [Google Research record](https://research.google/pubs/the-tail-at-scale/)
- **gRPC request hedging and cancellation [opened].** Living guides, accessed 2026-11-21, licence not stated on the cited pages. The guide applies a single deadline to the attempt chain, cancels outstanding RPCs after a winning response and supports retry throttling, nonfatal status codes and server pushback. Cancellation still requires cooperation from the server handler to stop its work. Reuse the semantics in the Python coordinator and test deadline, throttling and fast-failure cases without adopting gRPC. [Request Hedging](https://grpc.io/docs/guides/request-hedging/) · [Cancellation](https://grpc.io/docs/guides/cancellation/)
- **Google Authorized Buyers [opened].** Living docs, accessed 2026-11-21, CC BY 4.0 for text and Apache-2.0 for code samples. “How real-time bidding works” gives 80–1,000 ms depending on `BidRequest.tmax`, with late bids excluded. “Best Practices” describes a front end returning a default no-bid response on backend failure while preserving the connection, and compares behavior under overload. Transfer the exchange clock, early degraded result and connection reuse. A no-bid equivalent is financially different here because game defaults still transact. Test the writer with a stalled backend and a healthy connection. [RTB overview](https://developers.google.com/authorized-buyers/rtb/get-started/start) · [Best practices](https://developers.google.com/authorized-buyers/rtb/get-started/practices-guide) · [Peering](https://developers.google.com/authorized-buyers/rtb/get-started/peer-guide)
- **Russell and Zilberstein, *Composing Real-Time Systems*, IJCAI 1991 [opened].** No open reuse licence stated on the proceedings PDF. Section 2 distinguishes a contract algorithm, allocated a budget before it starts, from an interruptible one that can return its best intermediate result. It derives a geometric schedule with a factor-four runtime guarantee for this reduction under its assumptions. Treat each LLM call as a contract and the local best snapshot as the interruptible answer. Measure quality at fixed cutoffs with worker failures and jitter. No numerical transfer of the factor-four result is assumed. [Proceedings paper](https://ijcai.org/proceedings/1991/0032.pdf)

Start the backup about eight seconds after an on-time strong dispatch, with +12 s as the first checkpoint. Use a measured p90–p95 for the *stall indicator* on healthy requests as traces accumulate. Track time to meaningful output separately from connection and header time. Once meaningful output starts, predict remaining work from observed progress and the advertised schema. Admit a backup when `now + conditional p90 backup-to-valid + merge budget < 54 s`. Use at most one, launch sooner on an explicit eligible failure and let `Retry-After` block same-provider retries. For equivalent options, accept the first locally valid result and close the redundant stream. A fast-tier result alone should not cancel a strong attempt that can still improve important lines.

With primary valid-completion time `P`, backup `B` and delay `h`, an equivalent request finishes at `min(P, h+B)` whenever both attempts run. Under independence the miss probability at cutoff `D` is `Pr(P>D) × Pr(B>D−h)`. Estimate the joint miss directly on paired traces. With one backup at a genuine p95 trigger, about five rounds in 100 start a backup before accounting for early errors or disagreement triggers. Compare that to 100 guaranteed extra calls from immediate duplication. This is request arithmetic and gives no billing guarantee.

The app speculates by starting the strong path before the fast result is known. A delayed replica speculates about primary failure. Both consume inference capacity. Speculative decoding is a model-server technique that requires access to model internals. Leviathan et al., ICML 2023, reported 2–3× acceleration on T5-XXL against T5X in §4.1, with the same output distribution. Treat server-side decoding optimizations as part of a route's measured performance. Replay starting the strong path immediately versus waiting for the fast output. [Speculative decoding paper, arXiv v2 2023-05-18, CC BY 4.0](https://arxiv.org/html/2211.17192v2) [opened].

Use an endpoint/model breaker with closed, open and half-open states. Start with three consecutive transient failures in 30 minutes, open for five minutes or the provider's longer `Retry-After`, then probe once. A permanent auth, unsupported schema or exhausted-credit error disables that route until corrected. Open on explicit quota pushback for its stated duration. Set separate connect, read-idle, pool-acquisition and absolute cutoffs. Use a 1.5 s initial connect cap, a read-idle cap based on route traces and an absolute worker deadline of +54 s. Set provider SDKs to zero automatic retries on the timed path. The coordinator spends the single backup budget explicitly. [Azure Circuit Breaker pattern, living guide accessed 2026-11-21, licence not stated on the page](https://learn.microsoft.com/en-us/azure/architecture/patterns/circuit-breaker) · [OpenAI SDK retries](https://github.com/openai/openai-python#retries) [opened].

**Boundary for this case.** Whole-invoice text is cheap and preserves which jobs share a room, task or minimum call-out fee. Tier 1 handles all lines. Tier 2 sees all rows but may return updates only for the rows identified as consequential by local rules. Coverage and relatedness use policy clause references and the description. Price uses a justified unit rate and available evidence. Use photos for quantity or location and separate evidence for Munich unit rates. Shared line IDs, quantities, units and VAT originate from validated local inputs. Pass uncertainty to the existing `price_case` calculation. Apply map-reduce to a few high-impact exceptions. Each call estimates one independent row or group, and the local reducer retains all rows and checks for inconsistent coverage or duplicate call-out costs. For illustration, four required independent calls each with a 95% chance of finishing by the cutoff give only 0.95⁴ ≈ 81% for a complete result. A tier-0 base makes those four upgrades optional.

**Agreement starting gate.** Require identical validity class and clause evidence, compatible justified quantities, overlapping positive price intervals and unit-price medians within a factor of 1.25. Check that the resulting `(a,b)` change stays within a predeclared tolerable band, such as 10% on material lines, with a euro floor tuned on replay. Compare outputs generated without seeing each other. Shared documents and model training still create correlated mistakes. Agreement skips extra review on that line. If all material lines pass, stop scheduling samples and close redundant work if it has no remaining evidence to contribute. Adjudicate material contradictions against source evidence.

## Correctness and replay gates

1. **Clock and task graph.** Convert documented `start_time` to an absolute monotonic offset once shortly before the round using a synchronized wall clock. Resynchronize before the round and freeze that mapping for the active round. Use actual elapsed time even if the scheduler wakes late. Use `asyncio` and reusable async HTTP clients for I/O, deadline-scoped tasks and one writer. Catch individual provider errors at the task boundary so they do not cancel the watchdog. Threads are a viable migration path with bounded I/O, and `Future.cancel()` only stops work that has yet to run. Use a supervised subprocess with a time limit for archive extraction or a parser that can hang. Consider a process pool only if profiling shows sustained CPU contention. [Python tasks and timeouts](https://docs.python.org/3/library/asyncio-task.html) · [Python futures](https://docs.python.org/3/library/concurrent.futures.html) · [Python docs licence, living docs accessed 2026-11-21](https://docs.python.org/3/license.html) · [OpenAI Python SDK, Apache-2.0, accessed 2026-11-21](https://github.com/openai/openai-python) [opened].
2. **Immutable candidates.** Key by game ID and canonical line ID. Validate full line-set equality on every snapshot and reject nonfinite, negative, duplicate, unknown or mismatched records before pricing. Store lineage per field or line, candidate version, source route, evidence and timestamps. Compare candidates by a predeclared local quality gate. Use source grounding, known unit/quantity, consistency and demonstrated tier quality, with tier as a tie-break where justified. Preserve a supported earlier field if a later tier contradicts it without evidence. Multiple independent fields can yield a strictly stronger composite. Keep monotonic quality per retained line, forming an entire replacement payload each time. Hash canonical payload bytes and skip exact duplicates.
3. **One writer owns PUTs.** Track `best_validated`, `highest_sent`, `last_acknowledged` and an unresolved-send flag. Choose the maximum eligible queued snapshot before dispatch, including simultaneous results. Persist a small write intent with game, version and hash before sending. Keep large logs off the critical path. Verify the returned game ID, line indices and echoed prices where documented, then mark committed. On restart, use the journal and never restart blind from tier 0. The watchdog signals the same writer, so it cannot produce a concurrent downgrade. An observed terminal rejection or a proven pre-send connection failure permits a bounded retry or a new best snapshot before the cutoff. Use no automatic game retries in the HTTP client.
4. **Treat an ambiguous write as an ordering barrier.** PUT is idempotent for the intended effect of repeating the same payload. The documented last-write-wins endpoint offers no version precondition or idempotency key. If bytes may have reached the server and the ACK is lost, the old request can still commit after a newer one. Retry only the identical bytes and hash if time remains, and freeze upgrades that round while any older attempt is unresolved. A retry ACK by itself cannot prove the first attempt has stopped. Label the outcome uncertain if no ACK arrives. An authoritative terminal state for every in-flight version or a server-side version fence is necessary to safely resume upgrading after ambiguity. Never hedge two different submissions. [Game handbook](../../materials/API_HANDBOOK.md#put-apigamesgame_idsubmissions) · [RFC 9110 §9.2.2, 2022-06, IETF Trust terms in RFC notice](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2) [opened].
5. **Replay without live game calls.** Use an in-process simulator with a virtual clock. Model server commit and client ACK as separate events. Replay released case 0 and constructed invoices with labels for known clause or quantity mutations. Preserve line order permutations, unrelated items, absent photos and multi-line dependencies. For price, use blinded evidence bands from available dated public rates or reviewer quotes, record which lines lack them, and run synthetic payoff sensitivity over plausible `t` and opponent policies. Agreement, synthetic payoff and public leaderboard movement do not identify hidden fair thresholds. Run representative provider timing/cost samples separately on permitted data if later authorized. Retain paired traces and inject correlated slowdowns.
6. **Pass/fail and observability.** Inject delayed key, corrupt archive, primary PDF failure, both parsers failing, absent photo, refusal, 429 with pushback, 529, stalled SSE, unknown model output, clock drift, duplicate completion, ACK lost after commit, out-of-order server delivery and process restart. In feasible fixtures require a full tier-0 candidate by +5 and ACK by +10, zero lower-quality writes after higher versions, and no new model candidates promoted after +54. Track p50/p95/p99 for start lag, key, decrypt, parse, photo prep, queue, connect, upload, TTFT, first valid line, validation, writer queue and PUT ACK. Include failure types, cancelled and billed tokens, model/endpoint, cache reads/writes, snapshot version/hash, tier at +10/+54, terminal acceptance and exact replay seed. Report counts with tail quantiles. In 100 rounds the p99 is effectively an extreme observation. Report deadline hit rates over all rounds, including timeouts, alongside conditional latency among successes. Compare to the current two-call race at the same cost and score only quality proxies backed by evidence.
